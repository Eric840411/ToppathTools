UAT 積木工作台操作手冊

把一次手動測試錄成積木，之後每次都用同一組步驟重跑，跑完依 Lark 上的 TC 逐筆判定並回寫。這頁只回答四件事：怎麼跑、怎麼錄、結果為什麼是那個顏色、卡住怎麼辦。

01這是什麼

工具在 OSM Tools → UAT 整合測試。上方三個分頁是三條互不相干的線，腳本不能互換：

分頁測什麼怎麼指東西
BackendCP／NC 後台管理站DOM 選擇器
H5手機版遊戲大廳（Vue 網頁）DOM 選擇器
PC桌機版（Cocos 畫布）場景樹節點名稱或路徑
PC 沒有 DOM。整個畫面是一張 <canvas>，所以「驗證可見」這類選擇器積木在 PC 上永遠命中 0——不是選擇器寫錯。PC 要用場景／節點類的積木。

02跑一支現成腳本

頁面上方的 ①②③ 導引會顯示還缺什麼，點它就會跳到該填的地方。

  1. 左邊清單點一支腳本

    卡片上寫著誰建的、幾顆積木、綁了幾筆 TC、上次跑的結果與時間。

  2. 右邊「執行設定」填目標網址

    就是那支腳本要跑的站台網址（含 token 的完整網址）。解析度照預設即可，PC 用 1366×768 以上。

  3. 確認跑在哪台機器

    最上面那條狀態列。Local Agent 會實際開瀏覽器；沒有可派工的機器時按鈕會是灰的。

  4. 按「執行所選腳本」

    下方「即時執行日誌」會逐步顯示。要一次跑多支就勾選多份，再按「依序執行勾選的腳本」。

佇列一次只跑一份。中途失敗或取消時，後面的會全部標成「取消」，不是留在等待中——看到一排取消不代表它們待會兒還會跑。

03錄一支新腳本

  1. 按「錄製新腳本」

    （旁邊的「手動新增腳本」是另一件事：從空白自己拉積木，不會開瀏覽器。）

  2. 在開起來的瀏覽器裡照平常操作一次

    點擊、輸入、捲動都會被錄成積木。右上角那個小面板是錄製控制，可以暫停／停止。

  3. 要驗什麼，就開「加檢查」點它

    檢查模式下點畫面上的東西＝加一顆斷言，而且不會觸發原本的操作（點「Reserve Now」只會加一顆「這顆在」的檢查，不會真的去預約）。

  4. 停止錄製，回工作台綁 Lark TC

    在「執行設定」貼上 Lark 表格網址 → 掃描 → 勾選這支要對應的 TC。每一顆檢查積木都要指定屬於哪一筆 TC。

  5. 先試跑一次再交出去

    錄得起來不等於重播跑得過：畫面可能捲到不同位置、彈窗可能沒出現。

沒綁 TC 也能跑，只是不會回寫 Lark。清單上顯示「綁 0 TC」不代表腳本壞了。

04積木速查

積木分三種用途。只有「檢查類」會算成判定依據——一支腳本若一顆檢查都沒有，結果不會是 PASS。

操作類

積木做什麼適用
前往頁面開網址（留空＝用執行設定那一欄）全部
點擊元素用選擇器點Backend／H5
輸入文字填欄位Backend／H5
捲動畫面top／bottom／px，或把某個元素捲進畫面Backend／H5
按鍵盤Space／Enter／方向鍵（PC 的 SPIN 就靠這個）全部
PC 進機台等大廳就緒、挑一台可用的機台進去PC
PC 點節點點場景樹裡的節點；在清單裡會自動先捲進畫面PC
PC 捲動清單把指定的清單捲到某個位置PC

檢查類

積木驗什麼適用
驗證可見元素有出現在畫面上Backend／H5
驗文字／數字畫面上的字或數值。PC 讀 Cocos label，不是 OCR；數值模式可寫 >=100、<50全部

流程類

積木做什麼
等待停幾毫秒
截圖存證據，回寫時一起上傳到 Lark

WS 斷言要注意方向。send: 只證明「送出去了」，不代表 server 接受；要驗成功請再加一顆 recv: 或驗畫面狀態。

05會造成真實副作用的操作

這套工具跑在共用的 QA 環境上。下面這些按鈕按下去不是「畫面變一下」：

  • Reserve Now──把機台鎖 24 小時，別人進不去
  • 帶入額度／Join／PLAY NOW──動到餘額，而且佔住位子
  • 充值面板的 Confirm──真的轉錢
  • Cash Out──把機台裡的錢收回，結束那一輪

所以有一道守衛，擋在動作發生之前：

  • 錄製時：第一下會被擋下來問你。按確定後 15 秒內再按一次才會真的執行（不會幫你補按，因為「以為按下去了其實沒有」更糟）。
  • 執行時：積木上沒有勾「允許這個危險操作」就會停下來並說明原因。放行只對那一顆積木有效，不是整輪的開關。
正式環境一律不放行。網址看起來是正式（或模擬正式）站台時，連勾了「允許」也會被擋。判斷寧可從嚴——認不出來的網址一律當成正式。

06結果為什麼是這個

每一筆 TC 各自判定，同一支腳本裡一筆失敗不會拖累其他筆。

判定什麼情況Lark 上會變成
PASS 這筆 TC 底下的檢查至少有一顆，而且全部通過 勾 PASS，填通過時間，附截圖
FAIL 有檢查失敗，或有步驟執行不下去 勾 FAIL，附截圖
受阻 「前置條件」積木判定環境不具備（活動沒開、沒有第二台空機…）——沒測到，不是壞掉 兩個框都不勾，報告寫明缺什麼
待確認 一顆有效檢查都沒有（例如只截圖），或有警告級項目 兩個框都不勾
「受阻」和「待確認」在 Lark 上長得一樣（兩個框都不打勾），差別在報告裡的說明文字。要分辨請看執行結果那段敘述。

兩條容易被誤解的規則：只截圖不算檢查（會是待確認，不是 PASS）；同一筆 TC 裡真失敗與受阻同時發生時報 FAIL——受阻是「沒測到」，硬失敗是「測到了而且壞了」。

07卡住了

錄的時候好好的，重播說找不到元素

多半是捲動：錄的時候你往下捲過，重播時畫面停在最上面，那顆按鈕在視窗外（有些元素甚至是捲下去才生出來的）。加一顆捲動積木，或用「把元素捲進畫面」。

PC：點了沒反應／說位置在視窗外

先確認解析度夠大（1366×768 以上）。清單裡的節點會自動先捲進畫面再點；若仍在畫面外，通常是該頁根本沒開，或節點名打錯。

PC：點擊被中獎彈窗吃掉

大廳的 WIN THE JACKPOT 之類是畫在畫布上的節點，會攔截整個畫面的點擊。執行引擎全程會盯著關掉它們，日誌會寫「關掉 N 個彈窗節點」。

跑完了，Lark 沒有任何變化

三種可能：沒綁 TC（不回寫）；那筆 TC 底下沒有任何檢查（判待確認，兩個框都不勾，看起來像沒動）；回寫失敗——日誌會明寫，不會默默跳過。

執行時說「不支援的動作」

伺服器或 Local Agent 還在跑舊版。腳本用了新積木、執行端不認得，就會明確失敗（不會假裝跑過）。請重啟服務或更新 Agent。

腳本存起來卻顯示 0 區塊

舊版在用區網 IP（http://192.168.x.x）開啟時會發生，因為瀏覽器只在安全情境提供產生識別碼的 API。現已修正；若還遇到，改用 localhost 或 https 開，並回報。
