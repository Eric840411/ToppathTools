## 3. OSM Tools — OSM 版號同步（OsmPage）

**路由**：`/api/osm/*`, `/api/luckylink/*`, `/api/toppath/*`｜**歷史紀錄 feature key**：`osm-components`、`luckylink-components`、`luckylink-protocol-versions`、`toppath-components`、`osm-sync`、`osm-alert`

### 功能說明
追蹤 OSM / LuckyLink / Toppath 各元件版本，同步渠道機器設定，發送版本告警。

**LuckyLink SAS/MML/G2S 版本統計（2026-08-12）**：`GET /api/luckylink/protocol-versions`——登入 LuckyLink 後台（跟既有 `/api/luckylink/version-history` 同一組帳密/token 流程），分頁撈完整台 `/slot/egmList`（依回應 `total` 動態算頁數，`pageSize=50`，不是一次帶大 pageSize——已實測帶 `pageSize:2000` 這類超過後端實際上限的值會直接回空結果，必須照後台實際支援的分頁大小逐頁撈；已用真實資料驗證撈滿 1480/1480 台、共 30 頁）。

依 `sasversion` 欄位分類通訊協定：`'mml'` → MML、`'g2s'` → G2S、非空的其他值（例如 `'602'` 這類疑似 SAS 協定規格版號，**不是**字面上的 `'sas'` 字串——原本以為 SAS 機台會直接存 `'sas'`，已用全量 1480 筆真實資料驗證推翻這個假設）→ SAS、空字串 → NO_DATA（實測佔比最大，1300/1480，多數機台尚未回報協定資料）。**版號比對用 `clientversion` 欄位，不是 `sasversion`**——`sasversion` 只負責分類判斷是哪個協定，本身不是版本號（已用真實資料驗證：MML 機台的 `clientversion` 值為 `1.1.10`）。

SAS/MML/G2S 三組各自依 `name`（遊戲代碼）分組，組內列出每台機的 `gmid`／`clientversion`／連線狀態（`isactive`）；目標版本比對 `machine_type_targets` 表 `category='LuckyLink'` 底下的 `sas`／`mml_server`／`g2s_server` 三個 key（沿用既有「從 Lark 同步目標」機制，key-value 結構本來就支援任意新 key，同步端點本身零改動即可支援）。目標版本是「整個協定分類共用一個」，不是每個遊戲各自設定。`isactive` 只影響上線/離線徽章顯示，跟達不達標判斷無關（沒有目標版本時判定固定顯示「未設定目標」，不論線上線下）。NO_DATA 那 1300 台不列出逐筆明細（畫面效能與可讀性皆無意義），只顯示一行統計文字（總數＋其中離線數）；每個遊戲分組的機台明細表格預設收合，展開才顯示逐台清單。

### 機種渠道分布彈窗（2026-09-10，v4.135.0～v4.137.0）

同一個機種會散在好幾個渠道上，先前要找它在哪只能一個渠道一個渠道展開翻。點機台版本
Dashboard 上方的機種卡就列出分布。

**資料完全來自畫面上已有的 `channelResults`，沒有新的 API、不重新同步。**機種卡的數字本來就是
從它算的，只是 `allMachinesFlat`（`OsmPage.tsx`）那行 `channelResults.flatMap(c => c.machines)`
**flatten 時把「這台屬於哪個渠道」丟掉了**——渠道資訊一直都在，只是沒被用。

純判斷抽在 `src/pages/osm-gametype-dist.ts`（留在元件裡只能靠肉眼看），三個決定各有理由：

| 決定 | 為什麼 |
|---|---|
| **「只有離線機台」的渠道仍然要列出來**（顯示台數，列則被開關藏住）| 使用者要回答的問題是「這個機種在哪些渠道」。整段藏掉等於告訴他那個渠道**沒有**這個機種，而那可能正好是他在找的那台。**預設隱藏離線是使用者選的，但那是隱藏「列」不是隱藏「渠道」**——兩件事不能混 |
| **版本基準只看線上機台** | 離線機台的版本可能是很久以前的。算進去的話，一個離線很久的舊版本可能因為台數多而變成基準，把還在線上的正常機台全部標成異常。只有一種版本時不標色（沒有比較對象，標了只是雜訊）|
| **開關只影響「列」，不影響上面那些數字** | 數字描述的是部署現況，切開關讓數字跳動會讓人以為機台真的變多變少 |

**⚠️ 機種代碼的取法收成 `gameTypeOf()` 一支。**先前 `OsmPage.tsx` 裡有兩套：機種卡的數字
（`gameTypeCounts`）有「切不出中段就退回 `machineType`」那層，但「缺少機台」那段只寫了
`split("-")[1]`——**名稱裡沒有分隔號的機台會被算進卡片數字、卻永遠不會出現在缺少清單裡**。
彈窗一定要跟卡片同一套，不然彈窗台數會跟卡片數字對不上，所以順手收掉。

**⚠️「缺少機台」那段（`OsmPage.tsx` 的 `missingMachines`）目前還是自己那套 `split`，刻意沒改**
——改了會讓那份清單多出機台，屬於行為變更不是這次的範圍，待使用者確認。

**⚠️ 彈窗一定要走 `createPortal` 掛到 `document.body`**：這個版面的祖先有 `backdrop-filter`，
會把 `position: fixed` 困在容器裡（積木編輯器與錄製選擇器都踩過），不走 portal 會被裁掉。

> 已驗證 35 項（`npx tsx scripts/ui-checks/osm-gametype-dist.test.ts`，純函式＋讀原始碼的接線檢查，
> 不連服務）：機種代碼四種情況｜**全部離線的渠道仍在結果裡**｜沒有這個機種的渠道被濾掉｜
> 線上／離線／未知計數｜**離線版本再多也不會變成基準**｜開關前後的可見列｜不會就地改動來源陣列｜
> 接線：卡片點得開、**「缺少 N 台」的展開按鈕不會順便開彈窗**、走 portal、沒有第二套取法。
> **已注入違規確認會變紅**：濾掉全離線渠道 9 項紅、拿掉 `machineType` fallback 2 項、

#### 依型號（machineType）拆分（v4.136.0 拿錯欄位，v4.137.0 修正）

使用者實際用過之後要求「除了列出機台外，還要按 machinemodel 拆」。

**⚠️ 我第一次拿錯欄位。**「machinemodel」我理解成機殼型號，去撈了 `egmList` 的 `modelName`
（「Helix +」「Kaskada K43」這種），還為此在後端多帶了一個欄位。使用者指正「要拿這種的
dfdcgrand1」——他要的是 **`machineType`**（`dfdcgrand1`／`wlzbhelix25`／`lightninglink1`，
機種代碼 + 編號）。**這個欄位本來就在 `OsmMachine` 裡**，所以 v4.136.0 為 `modelName` 加的
後端欄位已整個收回，最終版是純前端改動、不需要重啟 server。

**教訓**：欄位語意不確定時，先把候選欄位的實際值拿給使用者看再挑，不要自己選一個然後做完。
我當時撈了 raw data、也看到 `machineType` 的值長什麼樣（probe 的輸出裡就有
`machineType → "lightninglink1"×28, "bbhl1"×24…`），但因為「model」這個字先入為主，
直接跳過它去挑了名字比較像的 `modelName`。**raw data 有撈到不等於有讀懂。**

**`machineType` 這個欄位很乾淨**（全渠道 1460 筆 egmList 實測）：

| 檢查 | 結果 |
|---|---|
| 空值 | **0 筆** |
| 大小寫／空白不一致 | **0 組**（65 種全部本來就是小寫）|
| 不以機種代碼開頭 | **1 筆**：CP 的 `4171-BWJL-9015` 型號是 `test3`（測試機）|

所以正規化只做 trim + 小寫防呆，**不需要**像 `modelName` 那種「哪些拼法算同一個」的判斷
（那個欄位一團亂：`Kascada K43`／`Kaskada K43`、`Helix`／`Helix +`、`KASCADA K27`／`Kascada K27`，
要合併得先去統一後台資料，不該在工具裡猜）。**編號不同一律視為不同型號**，不會因為前綴一樣併起來。

**⚠️ 排序用自然排序（數字部分按數值比），不是台數多寡。**真實資料裡 wlzbhelix 底下有 16 種型號
（wlzbhelix6、8、9、10…25，光 NP 一個渠道就 12 種），它本質上是一份版本清單，按名稱掃比較好讀；
而純字串排序會把 `wlzbhelix10` 排在 `wlzbhelix9` 前面。

**⚠️ 型號不以機種代碼開頭的照樣列出**（那筆 `test3`），不能因為「看起來不像這個機種的型號」
就藏掉——藏掉的話台數會跟渠道統計對不上，而且畫面上看不出少了東西。

**⚠️ 平手時的顯示寫法用 codepoint 順序，不用 `localeCompare`**（後者依環境的 locale 資料而變，
同一份資料在不同機器上會顯示不同寫法）。同一組裡有多種寫法時優先顯示「最多台在用」的那個。

**型號那一行永遠顯示，即使底下一台都不在線上**——它本身就是「這個渠道跑哪個型號」的答案，
跟渠道那層同一個道理。

**⚠️ 關閉鈕的 × 要用 flex 置中**，不能只靠 `lineHeight`：× 這個字元在 em box 裡本來就偏下，
使用者實際回報過「X 的位置在框框內偏下」。

> 已驗證 55 項（`npx tsx scripts/ui-checks/osm-gametype-dist.test.ts`），型號分組的案例**全部取自
> 真實 egmList 資料**：大小寫／前後空白算同一組｜**編號不同就是不同型號**｜`10pct` 那種變體獨立｜
> **自然排序（9 在 10 前面）**｜顯示最多台在用的原始寫法｜平手時穩定｜**`test3` 照樣列出**｜
> 沒有型號的那組不丟掉且排最後｜**分組前後台數守恆、每台只出現在一組**。
> **已注入違規確認會變紅**：把結尾編號去掉（等於把 wlzbhelix9/10/25 全併成一組）、排序退回純字串
> 比較、丟掉沒有型號的那組 → 合計 11 項轉紅。

不落 DB 也不在載入時還原，所以要看到彈窗得先對 8 個渠道的 OSM 後台真的同步一次。版面是
照使用者確認過的 mockup（`mockup-osm-gametype-channels.html`）實作的，邏輯有測試蓋住。
**v4.135.0 的版面由使用者實際點過確認**（回報了 × 偏下與要按型號拆這兩點）；
v4.137.0 的型號拆分我自己沒在畫面上看過，型號名稱與分布是用上面那份真實資料確認的。

#### 型號標籤：兩套外觀，生圖只出兩端裝飾（2026-09-12，v4.142.0～v4.142.1）

型號那行原本是純文字，跟底下機台名稱同色、字級只差 1px。一個渠道最多 16 個型號
（NP 實測 12 個）連排下來時掃不出層級。

改成銘牌：青玉光刃＋金符角標＋斜切角，hover 跑一次 420ms 掃光。

**⚠️ 第一次要 CodeX 生 30 幀 sprite 完全不能用，而且失敗的根因不是提示詞。**

| 問題 | 實測 |
|---|---|
| **文字燒在圖裡** | 每一幀都畫著 `dfdcgrand1`，但型號名是變動的（`wlzbhelix9`～`wlzbhelix10pct19`）|
| **不是同一動畫的 30 幀** | 框寬 275～304px、框高 99～137px、字級逐幀漂移 → 播起來會抖 |
| 幀編號也燒進去 | 左上角 `1`~`30` |

**AI 生圖是「畫 N 張很像的圖」，不是「畫一個動畫的 N 幀」。**再要一次還是一樣。
所以分工改成 **CodeX 只出靜態素材、動畫由 CSS 做**——這也是他自己第一則回覆本來就建議的。

**⚠️ 規格要寫長寬比與最終顯示尺寸，不要寫畫布尺寸。**我指定 1024×1024／512×512，
工具兩次都吐 1254×1254——**但那根本不影響**，因為收到後本來就會裁到圖形邊界再縮。
真正該講而我沒講的是「這東西最後只有 14×26 px」：他往「一張好看的完整劍」畫（長寬比 1:5.8），
整條放進 26px 行高會變成 **4px 寬的一條淡線，實測比純 CSS 漸層還弱**。
所以只取了核心段（1:1.16）。後來他又出一版「更乾淨」的，量下來 1:6.53 **更細**，沒採用。

**⚠️ 銘牌本體（底色／外框／斜切角）一律 CSS，不能出圖**：寬度隨型號名長度變，出圖會被拉伸。
只有兩端固定尺寸的裝飾件適合用素材。

素材收下前固定驗四項：真 alpha 且四角=0｜無文字無數字｜圖形不碰畫布邊緣｜不是整塊面板。
最終 `public/osm/modeltag-blade.png`（56×104）＋ `modeltag-rune.png`（33×48），合計 17KB。

**⚠️ alert 的判斷必須跟逐台標色那行完全一樣**（`refVersion` + 線上 + 版本不同）。
兩套判斷遲早漂移，症狀是「銘牌說這組有異常、底下每一台都沒標黃」，**而且兩邊都不會報錯**。
這不是新規則，只是把同一件事往上提一層。

**⚠️ 掃光只在 hover 跑，不常駐**（CodeX 也特別提）：16 個標籤同時動很吵也吃 CPU。
全離線的型號只降 `opacity` **不能 `display:none`**——它本身就是「這個渠道跑什麼型號」的答案，
跟渠道那層同一個道理（見上面 v4.135.0 那節）。
金符留了 `◆` 當備援字元、用 `font-size:0` 藏著，圖載不到時仍有東西可看。

#### 彈窗內搜尋：兩種「看不到」必須分得開（2026-09-12，v4.143.0）

比對 **渠道名稱／型號／機台名稱／版本** 四項，命中處高亮。版本也比對是因為真實資料裡
`1.18.10` 與 `1.17.40` 混在一起，打 `1.17` 就能挑出落後的那些。

判斷全在 `searchDistribution()`（`osm-gametype-dist.ts`），元件只負責畫。

**⚠️ 這個功能最容易出錯的地方是「有命中但全被離線開關藏住」——它跟「完全沒命中」在畫面上
長得一樣（都是一片空白），而使用者會把前者讀成「沒有這台機器」。**
（CodeX review 的重點，他原話：「不要讓畫面看起來像真的 0 筆」。）

| 狀態 | 呈現 |
|---|---|
| 有命中、被離線開關藏住 | 黃字「找到 N 台符合搜尋的離線機台，目前被『顯示離線機台』隱藏」＋**真的按鈕** |
| 完全沒命中 | 置中灰字空狀態 |

顏色、版位、有沒有按鈕全都不同。**「顯示離線」一定要是 `<button>` 不是一句可點的灰字**
——可行動提示要看起來可行動。

**三個行為決定**（跟 CodeX 討論定案）：

| 決定 | 為什麼 |
|---|---|
| **濾掉不符的列**，不是保留全部再標記 | 最大的機種有 141 台，標記等於還是要自己找 |
| 上方「分布在 N 個渠道、共 M 台」**不隨搜尋變動** | 那是部署現況。跟著搜尋跳動會讓人以為機台真的變少了。搜尋的縮放只在「符合 X / M 台」那一行表達 |
| **不自動打開「顯示離線」開關** | 搜尋偷改另一個篩選的狀態，使用者會搞不清畫面為什麼變了。改成給按鈕 |

**⚠️ 搜渠道名或型號時，整個渠道／整組要視為符合**（`wholeGroupHit`）——逐台比對的話
打 `NCH` 會什麼都不剩，因為機台名稱裡沒有渠道名。

**⚠️ 型號標籤上的分母、以及 alert 的判斷，一律看整組不是搜尋結果**：
分母用 `matched.length` 的話畫面會寫「1 / 1 台」，看起來像這個型號只有一台；
而「這個型號有沒有版本異常」是事實，不該因為搜尋縮小範圍就消失。

**⚠️ Esc 維持關彈窗，搜尋不記憶**（跟 CodeX 定案：不為這兩個加行為複雜度）。清除用輸入框的 ×。

**順手收掉一個已經長出來的重複**：`hasVersionMismatch()` 早就在純判斷模組裡（註解就寫著
它存在的目的是給型號銘牌用），但 v4.142.0 我在元件裡又寫了一份 `some()`。
那正是那支函式的註解在警告的事——畫面上兩個地方各自定義「異常」，
症狀是「標籤說這組有異常、底下每一台都沒標黃」，而且**兩邊都不會報錯**。已改成共用同一支。

> 已驗證 **140 項**（`npx tsx scripts/ui-checks/osm-gametype-dist.test.ts`，比上一版多 57 項）
> ＋ **12 項視覺**（`npx tsx scripts/ui-checks/osm-dist-search-states.ts`）。
> 後者**直接 import 真的 `searchDistribution()`**、配 build 出來的 CSS 渲染五個狀態並讀
> computed style——只重現「渲染」那一層，不重寫判斷（重寫一份就變第二套實作，漂了測試還是綠的）。
> 它驗的核心就是「兩個關鍵狀態的顏色／按鈕／區塊都不同」。
> **已注入違規確認會變紅**：搜渠道名不整組命中、分母跟著搜尋縮小、不回報被藏住的台數、
> 「顯示離線」退回灰字、元件自己再寫一份版本比對 → 各自轉紅，還原後回到 0。

> ⚠️ 版面是照使用者確認過的 mockup（`mockup-osm-dist-search.html`，可真的打字搜尋）實作的；
> **真實資料下的 141 台機種仍然沒有實際點過**（要先對 8 個渠道真的同步一次）。

### 使用者操作
| 操作 | 說明 |
|------|------|
| 查看版本歷史 | 列出 OSM / LuckyLink / Toppath 各元件的版本紀錄 |
| 同步元件版本 | 拉取最新版本資料，儲存到 DB |
| 同步全渠道 | 對所有渠道執行 machine push/pull，更新設定 |
| 手動觸發版本告警 | 比對各渠道版本，發現未達標項目推送 Lark 告警 |
| 設定排程告警 | 設定 cron 時間，定時自動版本告警 |
| 從 Lark 同步同步目標 | 從 Lark Sheet 讀取目標版本清單 |
| Config 比對 | 貼上渠道 URL，與 Template 比對設定差異 |
| Frontend 機台管理 | 查看 / 自動更新前端機台清單 |
| 取得 SAS/MML/G2S 版本 | LuckyLink 分頁下新區塊，抓取全部機台依協定分類、依遊戲分組顯示，與目標版本比對，NO_DATA 只顯示統計數字 |
| 查機種的渠道分布 | 機台版本 Dashboard 上方任一機種卡點下去，彈窗列出這個機種分布在哪些渠道、渠道底下再按型號（machineType，例如 dfdcgrand1）拆開、每台機器名稱／版本／連線狀態；預設只列線上，開關可顯示離線／未知；上方有搜尋欄可比對渠道／型號／機台名稱／版本，命中處高亮、不符的列濾掉。型號那行是獨立標籤，普通版是左側色條＋深底的樸素樣式、修仙版是銘牌（青玉光刃＋金符角標、滑鼠移上去跑一次掃光）；這組型號裡有版本跟基準不同的線上機台時，普通版色條轉黃、修仙版光刃轉金色低頻呼吸 |
