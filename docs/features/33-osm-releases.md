### 位置
OSM Tools → **OSM 版本更新紀錄**（修仙版：版本更新卷宗）。頁面 key `osm-releases`。

### 資料模型（`server/osm-release-store.ts`）
| 表 | 內容 |
|---|---|
| `osm_release_tabs` | 分頁（OSM／Toppath／PC_OSM／APP／OM ServerUpdate…）：是否有元件欄、SQL 執行欄、更新結果欄、啟用 |
| `osm_release_components` | 元件，屬於某個分頁；`group_name` 決定矩陣分組（例「組件」「LuckyLink組件」） |
| `osm_release_statuses` | 狀態清單（預設 測試服／維護上正式／熱更上正式），`tone` 只影響標籤顏色 |
| `osm_releases` | 一筆更新：分頁、狀態、測試日期、上線日期、更新內容、SQL、更新結果、`rev`（樂觀鎖）、`deleted`（軟刪除）、`source_key`（匯入冪等） |
| `osm_release_values` | 每筆 × 每個元件的**三態**：`updated`（有更新，必填版號）／`unchanged`（未異動，Lark 表上的 x）／`na`（未提供，Lark 表上的空白） |
| `osm_release_revisions` | 修改履歷：每次新增／修改／刪除／匯入存一份完整快照 |
| `osm_release_views` | 個人檢視（存篩選條件，只有自己看得到，上限 30 個） |

**三態不能混**：「未異動」跟「未提供」是不同的事（前者是確定沒動、後者是當時沒填），匯入、畫面、規則都分開處理。

### 規則（`shared/osm-release-rules.ts`，前後端共用一份）
- 狀態必選；測試日期、上線日期至少填一個；上線不能早於測試；日期必須是真的日期
- 有更新必填版號；未異動／未提供不能填版號
- 有元件欄的分頁：至少一個元件有更新，或有寫更新內容；沒有元件欄的分頁（OM）：更新內容必填
- 停用的狀態／元件不能新選；**舊紀錄原本就用著的可以保留**（編輯時帶 `keepIds`）
- 新紀錄沒動過的元件預設「未異動」；**舊紀錄沒有值的元件（之後才加的）維持「未提供」**，存檔不會偷偷改掉
- **編輯時「沒送＝保留原值、送空字串＝清空」**（`mergeUnsentFields`，PUT 路由在驗證前先補）：
  - 畫面上隱藏的欄位（SQL／更新結果／元件欄）**整個不送**（前端 `toUpdateBody`），不是送空字串
  - 後端**只看有沒有送，不看伺服器現在的分頁設定**：設定改了不會讓紀錄 rev 變、不會 409——A 開表單時欄位隱藏、B 之後打開，
    A 的舊表單照樣不帶那欄，拿現在的設定判斷就會把它清掉
  - 編輯用的 schema（`releaseUpdateSchema`）這三欄是 optional、**不能加 `.default('')`**，否則「沒送」跟「送空的」會被抹成同一種
  - values 沒包含的元件（元件欄隱藏、或畫面拿的是舊設定不認得別人剛加的元件）保留原值；要清掉一個元件的值必須明確送「未提供」
  - CodeX 1022 審 b160ed5 兩個 [P1]＋32539a1 一個 [P1]，三個都實際重現過會刪資料

### 權限（三層，權限管理頁按角色勾選；後端每支 API 都驗，不是只藏按鈕）
| key | 能做什麼 |
|---|---|
| `osm-releases` | 查看 |
| `osm-releases-edit` | 新增／編輯紀錄 |
| `osm-releases-manage` | 設定（分頁／元件／狀態）、刪除紀錄、從 Lark 匯入 |

編輯／管理都隱含查看（側欄 `canAccess` 與後端 `need()` 同一個判斷）。管理員一律全開。預設只有管理員。

### API（`server/routes/osm-releases.ts`）
`GET meta`（分頁／元件／狀態／筆數／最後更新／我的權限）、`GET list?tab=`、`GET :id/revisions`、`POST /`、`PUT :id`（帶 `rev`，不符回 **409 CONFLICT** 並附最新那筆）、
`DELETE :id?rev=`、`POST tabs|components|statuses`、`PUT components/:id|statuses/:id`、`DELETE components/:id`、`POST reorder`、`POST import`、`GET/POST/DELETE views`、`GET live?tab=toppath`。

### 使用者可執行的操作
- 切分頁（顯示各分頁筆數）
- **時間軸**：按月份分組，卡片顯示日期、狀態、有更新的元件版號、內容第一行；點卡片看右側詳情（元件版號、內容、SQL、更新結果、單號、修改履歷）
- **矩陣**：橫向核對各元件版號；元件群組可收合（預設只展開第一組），收合後顯示該組有更新的元件；點一列跳回時間軸看詳情
- 篩選：搜尋（單號、內容、版號）、月份範圍（下拉，只列有紀錄的月份）、狀態、元件（多選）；**我的檢視**存目前篩選、一鍵套用、刪除
- 新增／編輯（寬側欄）：元件逐列三態、有更新才出現版號欄；更新內容會自動辨識單號（只標示，不做連結）；
  有未儲存內容時關閉／離開頁面會提醒；別人先存了會顯示「誰在幾點改過」，可改用最新版本重新編輯（不會覆蓋別人的修改）
- 修改履歷：每一版是誰、何時、做了什麼，修改會列出哪些欄位從什麼變什麼
- 刪除（管理設定）：軟刪除，列表看不到但履歷保留
- Toppath 分頁：詳情顯示 GM／API／GW／TG-API 的線上目前版本（staticpublic 版本 JSON），跟這筆的版號相同會打勾。其他元件沒有線上來源，不顯示
- 只有查看權限：頁首標「唯讀」，新增按鈕反灰並說明需要的權限；設定、編輯、刪除不顯示
- **設定**（管理設定）：
  - 分頁：改名、勾選元件欄／SQL／更新結果、排序、停用、新增
  - 元件：依分頁列出，改名、改群組、排序、停用；被引用 0 筆的才能刪除（「被引用」不算未提供）
  - 狀態清單：改名、色系、排序、停用、新增
  - 從 Lark 匯入：貼 Wiki 或試算表網址，每個頁籤匯成一個分頁、表頭元件建成元件；**重跑只補沒匯過的列**；沒有日期欄的頁籤（選取目錄）自動略過並列出原因

### Lark 表的形狀（匯入用，`server/osm-release-import.ts`）
- 第 1 列：測試日期／更新狀態／上線日期／元件大類（合併格）／更新內容／SQL執行（OSM 才有）／更新結果（OM 才有）
- 第 2 列：元件名稱（OM ServerUpdate 沒有，第 2 列直接是資料）
- 日期是 Excel 序號；元件格 `x` ＝ 未異動、空白 ＝ 未提供、其他 ＝ 版號
- 冪等：`source_key` ＝ 表 token＋sheet id＋列號

### 踩坑
- 元件「被引用數」跟「能不能刪」原本定義不同（一個不算未提供、一個算），畫面顯示 0 筆給刪除按鈕、後端卻拒絕——兩邊改成同一個定義，測試守住
- 「畫面沒顯示」不等於「使用者要清掉」：表單只送看得到的欄位，後端整筆覆寫就會刪資料。補值放在後端，不靠前端記得帶
- 衝突重編要連設定一起重讀，不然用舊設定重建表單會漏掉別人新加的元件
- 兩版都不用原生 emoji（CodeX 設計稿要求）
- 月份篩選不能用 `<input type="month">`：Safari／Firefox 桌機版不支援，退化成空白文字框（v5.67.1 使用者回報；我只用 Chromium 截圖所以沒看到）。改成下拉選單，選項是實際有紀錄的月份。**有原生輸入元件的畫面要用 WebKit 也截一次**
- 側欄與彈窗用 `createPortal` 掛 body（祖先有 `backdrop-filter`），所以 CSS 變數要同時定義在 `.orl-page` 與 `.orl-portal`
